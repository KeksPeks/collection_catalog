# Прогресс проекта Collection Catalog

Последнее обновление: 2026-08-25

## Текущий рабочий процесс
- Основная рабочая ветка: `develop`.
- Изменения после проверки интеграционной ветки переносятся в `develop`.
- Локальная рабочая копия: `D:\FlutterProjects\collection_catalog`.
- Каталоги данных проекта: `E:\collection_catalog`.

## Последнее подтверждённое состояние
- Интеграционная ветка была очищена от конфликтов и проверена.
- Изменения перенесены в `develop`.
- Локальная сборка после синхронизации с `origin/develop` успешно запускается.
- `flutter analyze` на актуальном `develop` проходит.
- `flutter test` проверен в процессе интеграции.
- Последний успешный CI для `develop`: commit `03e12d3163515cdd9e4c732987225d92946c4f69`.

## Выполненные изменения, подтверждённые пользователем
- Убрана пользовательская настройка фиксированной высоты карточек.
- Размер карточек/колонок должен определяться содержимым и доступным пространством.
- Настройки интерфейса перенесены из инструментов коллекционера в обычные настройки.
- Настройки количества колонок синхронизированы между каталогом и избранным.
- Исправлялись ошибки `Bottom overflowed` при увеличении количества колонок.
- В каталоге убран лишний вывод вида `1 выберите каталог`.
- При нескольких колонках значок и название должны центрироваться.
- Если текст не помещается в карточку при выбранном числе колонок, допускается скрывать текст, оставляя значок.
- Для отсутствующих изображений используется `No image`/аналогичная локализованная подпись.
- Для стран предусмотрено отображение соответствующего флага вместо обычного значка изображения.
- Добавлялась локальная геймификация: достижения и статистика должны работать непосредственно на устройстве, без обязательного сервера.
- Раздел `Обзор` должен показывать статистику и служить местом отображения геймификации.
- В разделе `О приложении` должна быть кнопка просмотра истории версий и изменений.
- В настройках убран вывод номера версии там, где пользователь просил его убрать.

## Важное текущее состояние
- Последняя проверка пользователя: «Всё работает».
- Текущую рабочую копию не считать источником изменений, пока она не синхронизирована с `origin/develop`.
- Перед следующими изменениями сначала синхронизировать локальный `develop` с GitHub.
- После новых изменений выполнять полный цикл: запуск -> проверка -> сборка -> повторная проверка.

## Что ещё контролировать
- Наличие всех функций в реальном интерфейсе, а не только в коде.
- Корректность подсчёта статистики и достижений.
- Отображение достижений в `Обзор`.
- Историю версий в `О приложении`.
- Скорость загрузки `Обзора`.
- Ошибки загрузки каталога.
- SQLite ошибки в `Моих коллекциях`.
- Адаптивную высоту строк/карточек относительно шрифта и содержимого.
- Отсутствие `Bottom overflowed` при всех вариантах количества колонок.
- Локализацию всех добавленных строк.

## Принцип работы
Не возвращаться к удалённой настройке фиксированного размера интерфейса без отдельного запроса пользователя. Новые функции сначала реализовывать локально в приложении; сервер для достижений не требуется.
