# Public catalog and user collections

## Цель

Приложение должно позволять любому пользователю получить общий каталог и вести собственную коллекцию, не изменяя общий каталог.

## Архитектура

```text
Internet
   |
 HTTPS API
   |
 FastAPI
   |-------------------|
 PostgreSQL          Storage
                     G:\CollectionServer\images
                     G:\CollectionServer\downloads
```

### Общий каталог

Эти данные являются общими для всех пользователей:

- `collection_types`
- `categories`
- `collections`
- `items`
- `item_images`
- `item_files`

API только читает эти данные для обычных пользователей.

### Личная коллекция

Пользовательские данные должны быть отделены от каталога. Один и тот же `item` может принадлежать многим пользователям.

Минимальная модель:

- `users` — учётные записи;
- `user_items` — состояние предмета у конкретного пользователя;
- `user_collections` — пользовательские списки/коллекции при необходимости;
- `user_item_notes` — заметки, если их потребуется отделить от основного состояния.

Рекомендуемое состояние `user_items`:

- `owned` — владеет ли пользователь предметом;
- `quantity` — количество;
- `wishlist` — находится ли предмет в желаемом;
- `condition` — состояние;
- `purchase_price` — цена покупки;
- `purchase_date` — дата покупки;
- `notes` — личная заметка.

## Безопасность

1. PostgreSQL не публикуется в Интернет.
2. Публично доступен только HTTPS API.
3. `G:\CollectionServer\images` и `G:\CollectionServer\downloads` выдаются только через проверенный относительный путь.
4. Нельзя передавать абсолютные пути или использовать `..` для выхода из разрешённого каталога.
5. Пароли пользователей не хранятся в открытом виде — только Argon2id/bcrypt-хеши.
6. JWT/access tokens не должны содержать пароль или другие секреты.
7. Административный доступ к серверу оставляем через Tailscale.
8. Для публичного API используем HTTPS и ограничение CORS только необходимыми клиентами.

## Доступ

### Администратор

```text
Администратор -> Tailscale -> сервер
```

Tailscale используется для управления машиной и PostgreSQL/API в закрытой административной сети.

### Обычный пользователь

```text
Телефон/ПК -> HTTPS -> публичный API -> каталог + собственная коллекция
```

Пользователю не нужен Tailscale.

## Важное ограничение текущего домашнего сервера

Домашний ноутбук за NAT нельзя считать готовым публичным сервером только после установки Tailscale. Для публикации API нужен один из вариантов:

- проброс TCP 443 на роутере + HTTPS reverse proxy;
- публичный туннель;
- VPS/reverse proxy перед домашним сервером.

Предпочтительно: HTTPS reverse proxy с доменным именем, при этом PostgreSQL остаётся доступным только локально.

9. После успешных проверок перенести изменения в `main`.
