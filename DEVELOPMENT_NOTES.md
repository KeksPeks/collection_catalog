# Collection Catalog — заметки разработки

## 2026-09-01

### Подключение Flutter к существующему API

- Все изменения выполнены в ветке `develop`.
- Добавлен `lib/core/network/api_client.dart` на базе Dio.
- Добавлен `lib/features/collections/data/repositories/collection_repository_api.dart`.
- `collectionRepositoryProvider` теперь получает список коллекций из `GET /api/collections`.
- Локальный Drift-репозиторий сохранён как backend для текущих операций записи, чтобы не ломать существующее редактирование до появления API-команд записи.
- Идентификаторы серверных коллекций преобразуются в `String`, как требует текущая domain-модель Flutter.
- Ответ API передаётся Dio как JSON; Unicode не перекодируется вручную и должен отображаться в приложении корректно.
- Для Android добавлены `INTERNET` и разрешён HTTP-доступ к локальному серверу.
- Адрес API можно задать через `--dart-define=COLLECTION_API_BASE_URL=...`.
- Значение по умолчанию: `http://127.0.0.1:8000` (подходит для Windows/локального запуска; для физического Android-устройства нужен LAN-адрес ПК).

### Первый уровень каталогов

- В `lib/features/catalogs/data/catalog_section_defaults.dart` заложен первый уровень структуры каталогов.
- Первый уровень трактуется как подкатегории/бренды/типы, а не как отдельные предметы коллекции.
- Для `lego` первый уровень: LEGO, MEGA, K'NEX, Meccano, Lincoln Logs, Magformers, Geomag.
- Для остальных каталогов заложены соответствующие группы первого уровня по шесть наименований.
- Для LEGO сохранены дочерние уровни серий как основа для дальнейшего расширения каталога.
- Для остальных направлений структура подготовлена так, чтобы следующие уровни добавлялись через `children` без изменения модели каталога.
- Локализация названий первого уровня выполнена на русском там, где это тип/категория; официальные названия брендов и серий сохранены.
- Каталог `discs` также получил первый уровень платформ.

### Второй уровень каталогов

- Добавлен `lib/features/catalogs/data/catalog_second_level_defaults.dart`.
- Второй уровень подключается централизованно через `CatalogStructureDefaults.apply()`.
- Для каждого заложенного первого уровня добавлено по шесть элементов второго уровня.
- Второй уровень содержит серии, поколения, разновидности или тематические группы в зависимости от типа каталога.
- Названия официальных серий/брендов сохранены, типовые категории локализованы на русском.

### Третий уровень каталогов

- Добавлен `lib/features/catalogs/data/catalog_third_level_defaults.dart`.
- Третий уровень подключается после второго уровня через `CatalogStructureDefaults.apply()`.
- Для всех основных каталогов предусмотрены специализированные наборы третьего уровня, с общим fallback для новых направлений.
- Третий уровень предназначен для уточнения типа, выпуска, формата или разновидности перед конкретным предметом.
- Четвёртый уровень оставлен для конкретной единицы коллекции: набора, карты, монеты, книги, игры и т. п.

### Важно

- PostgreSQL данные не изменялись.
- Ручная перекодировка данных в БД не выполнялась.
- Сервер запускается отдельно перед проверкой.
- Перед переносом в `main` требуется выполнить запуск приложения и две проверки работоспособности на `develop`.
